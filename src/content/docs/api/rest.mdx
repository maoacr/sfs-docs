Todas las rutas que no son públicas requieren autenticación vía cookie `sfs_token` (JWT). Las rutas de administración requieren además rol `OWNER`.

## Capas de seguridad

Cada request a la API pasa por las siguientes capas en orden:

| Capa | Qué hace | Error |
|------|----------|-------|
| **Rate limiting** | Limita requests por IP/endpoint en ventana de tiempo | `429 Too Many Requests` |
| **CSRF** | Verifica token CSRF en métodos POST/PUT/PATCH/DELETE | `403 Forbidden` |
| **Auth (JWT)** | Verifica cookie `sfs_token` y rol requerido | `401 Unauthorized` / `403 Forbidden` |
| **Zod validation** | Valida body y query params contra schemas tipados | `400 Bad Request` + detalles |
| **Tenant isolation** | Filtro automático de `tenantId` en todas las queries multi-tenant | Transparente |

### Rate limiting

| Endpoint | Límite | Ventana |
|----------|--------|---------|
| `POST /api/auth/login` | 5 | 1 minuto |
| `POST /api/auth/register` | 3 | 1 minuto |
| `POST /api/reservas` | 10 | 1 minuto |
| `GET /api/disponibilidad` | 60 | 1 minuto |
| Resto de endpoints | 100 | 1 minuto |

Headers de respuesta: `X-RateLimit-Remaining`, `X-RateLimit-Reset`.

### CSRF

Los métodos `POST`, `PUT`, `PATCH`, `DELETE` de las rutas con `apiHandler` requieren header `X-CSRF-Token` que coincida con la cookie `csrf_token`. La cookie se emite en login/registro y `GET /api/auth/me` la renueva. En el frontend, `apiFetch` (`src/lib/api-client.ts`) envía el header automáticamente.

Excepciones: `POST /api/auth/login` y `POST /api/auth/register` no requieren CSRF (no hay sesión aún).

### Tenant isolation

Cada query a modelos multi-tenant (Complejo, Cancha, Reserva y sus recursos hijos) filtra explícitamente por el `tenantId` del dueño autenticado. Ver [Guía de Seguridad](/guides/security).

### Login

```json
POST /api/auth/login
Content-Type: application/json

{
  "email": "dueno@test.com",
  "password": "test1234"
}

// 200 OK
{
  "user": {
    "id": "uuid",
    "email": "dueno@test.com",
    "nombre": "Carlos Andrés Gómez Pérez",
    "apodo": "carlitosgomez",
    "role": "OWNER"
  }
}

// 400 Bad Request — datos inválidos
{
  "error": "Datos inválidos",
  "details": [
    { "path": "email", "message": "Email inválido" }
  ]
}

// 429 Too Many Requests — rate limit excedido
{
  "error": "Demasiadas solicitudes. Intenta de nuevo más tarde."
}
```

### Registro

```json
POST /api/auth/register
Content-Type: application/json

{
  "email": "nuevo@test.com",
  "password": "test1234",
  "primerNombre": "Pedro",
  "segundoNombre": "",
  "apellidos": "Ramírez",
  "apodo": "pedroramirez",
  "codigoPais": "+57",
  "telefono": "3001112233",
  "role": "PLAYER"
}

// 201 Created
{
  "user": {
    "id": "uuid",
    "email": "nuevo@test.com",
    "nombre": "Pedro Ramírez",
    "apodo": "pedroramirez",
    "role": "PLAYER"
  }
}

// 409 Conflict — email duplicado
{
  "error": "El email ya está registrado"
}
```

**Validaciones**:
- `password`: 8-72 caracteres
- `apodo`: 3-30 caracteres, solo letras y números
- `primerNombre`: 1-50 caracteres, requerido
- `apellidos`: 1-100 caracteres, requerido
- `role`: "OWNER" o "PLAYER", requerido
- `codigoPais`: default "+57"


## Reservas

| Método | Ruta | Auth | Rate Limit | CSRF | Descripción |
|---|---|---|---|---|---|
| `GET` | `/api/reservas` | ✅ | default | ❌ | Lista reservas (owner ve sus canchas, player ve las propias) |
| `POST` | `/api/reservas` | ✅ | 10/min | ✅ | Crea una reserva (estado: `PENDIENTE_PAGO`) |
| `PUT` | `/api/reservas/[id]` | ✅ | default | ⚠️ pendiente | Cambia estado (`CANCELADA` aplica política de reembolso; `COMPLETADA` solo el dueño) |

### GET query params

| Parámetro | Tipo | Descripción |
|---|---|---|
| `fecha` | `YYYY-MM-DD` | Filtra por día **en la zona horaria del complejo** de cada reserva |
| `estado` | `PENDIENTE_PAGO\|CONFIRMADA\|COMPLETADA\|CANCELADA` | Filtra por estado |

### Crear reserva

```json
POST /api/reservas
X-CSRF-Token: <token>

{
  "canchaId": "uuid",
  "fecha": "2026-09-25",
  "hora": "19:00"
}

// OWNER puede incluir:
{
  "canchaId": "uuid",
  "fecha": "2026-09-25",
  "hora": "19:00",
  "playerId": "uuid"
}
```

`fecha` y `hora` son **hora local de la cancha**. El servidor calcula el instante con `complejos.zona_horaria` y el fin con `duracionSlotMinutos`. Ejemplo: `2026-09-25 19:00` en `America/Bogota` se guarda como `slotInicio: 2026-09-26T00:00:00Z`.

**Validaciones**: el turno debe estar dentro del horario de apertura de ese día (`400` si no) y, para jugadores, no puede estar en el pasado.

## Pagos

Todas requieren autenticación. El pago se procesa vía MercadoPago Checkout Pro con Split 1:N (85% owner, 15% plataforma).

| Método | Ruta | CSRF | Rate Limit | Descripción |
|---|---|---|---|---|
| `POST` | `/api/reservas/[id]/pagar` | ❌ | strict | Inicia pago (mínimo 50% del total) |
| `POST` | `/api/reservas/[id]/pagar-saldo` | ❌ | strict | Paga saldo pendiente de reserva PAGO_PARCIAL |
| `POST` | `/api/reservas/[id]/confirmar-pago` | ❌ | default | Owner confirma pago manualmente |
| `PATCH` | `/api/reservas/[id]/cancelar` | ❌ | default | Cancela reserva con política de reembolso |

### Iniciar pago

```json
POST /api/reservas/:id/pagar

{
  "monto": 15000
}

// 200 OK
{
  "reservaId": "uuid",
  "monto": 15000,
  "checkoutUrl": "https://www.mercadopago.com.co/checkout/v1/redirect?pref_id=...",
  "tipo": "split"
}

// 400 — monto insuficiente
{
  "error": "El pago mínimo es del 50% (15.000 COP)"
}
```

**Reglas**:
- Monto mínimo: 50% del `montoTotal` (solo en primer pago desde `PENDIENTE_PAGO`)
- Monto máximo: `saldoPendiente` actual
- Si el split falla, usa Checkout Pro estándar como fallback

### Pagar saldo

```json
POST /api/reservas/:id/pagar-saldo

{
  "monto": 15000
}
```

**Reglas**:
- Solo para reservas en estado `PAGO_PARCIAL`
- Cualquier jugador del partido asociado puede pagar (pagos compartidos)
- Monto debe ser > 0 y ≤ saldo pendiente

### Cancelar reserva

```json
PATCH /api/reservas/:id/cancelar

{
  "motivo": "No puedo asistir"
}

// 200 OK
{
  "reservaId": "uuid",
  "estado": "CANCELADA",
  "porcentajeReembolso": 80,
  "reembolsos": [{ "pagoId": "uuid", "monto": 12000, "resultado": "ok" }],
  "motivo": "No puedo asistir"
}
```

**Política de reembolso**:
- Dentro del plazo (`plazoCancelacionHoras`) → 100%
- Fuera del plazo → 100% − `penalizacionPorcentaje`
- Dueño cancela → siempre 100%
- Reembolso automático vía MercadoPago

## Webhook MercadoPago

| Método | Ruta | Auth | Descripción |
|---|---|---|---|
| `POST` | `/api/webhooks/mercadopago` | ❌ (HMAC) | Recibe notificaciones de pago de MP |

**Seguridad**: Ruta pública en el proxy (MP llama sin cookie). Verifica la firma HMAC-SHA256 de `x-signature` sobre el manifest `id;request-id;ts` con `MP_WEBHOOK_SECRET`.

**Flujo**:
1. MP envía POST con headers `x-signature` y `x-request-id`
2. Sistema verifica la firma
3. Consulta el pago a MP API (doble verificación)
4. Busca el `Pago` por `external_reference` (id del pago) y lo aplica en una transacción idempotente
5. Si pago completo → `CONFIRMADA`, si parcial → `PAGO_PARCIAL`
6. Envía notificaciones al jugador y dueño

**Respuestas**: `200` si se procesó o se ignoró (duplicado, otro tipo de evento), `401` firma inválida, `500` error inesperado (MP reintenta).

## Cron

| Método | Ruta | Auth | Descripción |
|---|---|---|---|
| `GET` | `/api/cron/liberar-expiradas` | ❌ (CRON_SECRET) | Libera reservas PENDIENTE_PAGO expiradas |

**Configuración**: Vercel Cron ejecuta cada 5 minutos (`*/5 * * * *`). Ruta pública en el proxy; requiere header `Authorization: Bearer {CRON_SECRET}` y rechaza todo si `CRON_SECRET` no está definido.

**Acciones**: Cancela las reservas `PENDIENTE_PAGO` con más de 15 minutos y notifica a jugador y dueño. Las `PAGO_PARCIAL` no expiran.

## Seguridad

- **Tenant isolation**: explícita. Cada query a modelos multi-tenant filtra por `tenantId` o verifica la pertenencia del recurso padre.
- **Cookies HttpOnly + SameSite=strict**: `sfs_token` y `sfs_refresh` no son accesibles desde JavaScript ni se envían en requests cross-site.
- **bcrypt**: contraseñas hasheadas con 12 rounds.
- **JWT**: access token expira en 15 min, refresh token en 7 días.
- **Rate limiting**: implementado con sliding window en memoria. Configurable por endpoint.
- **CSRF**: double-submit cookie pattern. Requerido para todos los métodos unsafe (excepto login/register).
- **Input validation**: Zod v4 en todas las rutas refactorizadas. Valida tipos, rangos, formatos y reglas de negocio.

Para más detalles, consultá la [Guía de Seguridad](/guides/security).
